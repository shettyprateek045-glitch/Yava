# Week 1 — Project Planning & Strategy Design (Technical Component)

**Project:** Predicting Customer Churn for a Subscription-Based Streaming Service

The Week 1 deliverable is primarily the DOC project plan. This folder contains
the accompanying technical artifacts that give the plan something concrete to
point to on GitHub:

| File | Purpose |
|---|---|
| `generate_dataset.py` | Generates the synthetic `data/churn_dataset.csv` (5,000+ rows) used as the stand-in dataset for the whole project. Includes realistic messiness — missing values, outliers, duplicates — mirroring what's described in the plan's data-collection section. |
| `setup_project_structure.py` | Scaffolds the target repository layout (`data/`, `src/`, `notebooks/`, `models/`, `reports/`) proposed in the plan. |
| `diagrams.py` | Generates the methodology flowchart and system architecture diagram (Graphviz). |
| `data/churn_dataset.csv` | Output of `generate_dataset.py` — the dataset used by Weeks 2–4. |
| `reference_project_layout/` | The full target folder structure, populated with real working code — see its own `README.md`. |
| `outputs/diagrams/01_methodology_flowchart.png` | End-to-end project methodology (data collection → cleaning → EDA → feature engineering → modeling → tuning loop → evaluation → reporting → deployment). |
| `outputs/diagrams/02_system_architecture.png` | Data-flow architecture: raw data → ETL → processed store → EDA/features → model registry → reports → stakeholders. |

## How it connects to the DOC plan
- **Data source (Section: Methodology)** → simulated by `generate_dataset.py`
- **Repository/architecture strategy** → implemented by `setup_project_structure.py`
- **Strategic diagrams (Section: Methodology & Strategy)** → generated by `diagrams.py`; drop these PNGs directly into the DOC file as figures
